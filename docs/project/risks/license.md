# IP Licensing Risk — Three Tracks

The original draft rated this as **High likelihood / Critical impact** with mitigation: *"If this game is commercial, lock licensing. If it's a portfolio piece / fan project, communicate that publicly and don't monetize until cleared."* That's a restatement of the risk, not a mitigation. This file defines three concrete tracks.

The Metabarons saga is © Humanoids / Jodorowsky / Gimenez. Producing a derivative game requires either explicit licensing, fair-use justification (limited), or a non-commercial fan-project framing.

## Track A — Commercial release

**What this looks like.** v1.0 launches as a paid product (subscription, single-purchase, or BYOK with a paid wrapper). Marketing positions the game publicly as a Metabarons adaptation.

**What's required.** Engage Humanoids for an IP license **before Phase 2** (because Phase 2 introduces image generation, and image gen of Metabarons-tagged scenes meaningfully escalates the legal surface).

**Decision deadline.** End of Phase 1. If license is not secured by then, do not begin Phase 2 image-gen work; consider Track B or C instead.

**Cost.** Unknown. Negotiated. Could be a flat license, a royalty share, or a co-development arrangement.

**Risk if pursued.** Negotiation may fail or take longer than Phase 1's three months. Mitigation: parallel-path Track C as a fallback.

## Track B — Portfolio / fan project

**What this looks like.** Game launches as a non-commercial creative work. Public statement: "This is a fan project. It is not affiliated with Humanoids or the Jodorowsky/Gimenez estate." No monetization. BYOK-only as a *technical necessity*, not a business model.

**What's required.** Public framing from launch onward. Domain name, marketing copy, in-game disclaimers all consistent. No paid tier, no premium features, no merch.

**Decision deadline.** Soft — can be chosen at any phase boundary. Easier to start here and switch to Track A later than the reverse.

**Risk.** Humanoids may still issue a takedown. Fan-project framing reduces but does not eliminate that risk. Mitigation: respond to takedown promptly; have Track C ready as fallback.

## Track C — Original IP fallback

**What this looks like.** Same architecture, different world. The Metabarons-specific cards, lore, and references are stripped out and replaced with an original IP designed to occupy the same narrative shape (a multi-generational saga with refracted-knowledge inheritance).

**What's required.** A new IP brief. ~2-3 weeks of design work to author the original world. ~1-2 weeks of engineering to swap lore. Total: ~1 month of work.

**Decision deadline.** Anytime. Track C is the architectural escape hatch — the engine generalizes, so the IP can change without breaking the project.

**Cost.** ~1 month of team time. The architecture and 80% of the engineering carry over.

**Risk.** The team loses the leverage of the user's existing Metabarons depth. Mitigation: the user's authoring chops transfer to the new IP; the *shape* of the work (refracted-knowledge dynasty) is what matters, not the specific characters.

## Decision criterion

By **end of Phase 1**: Track A or B is committed; Track C remains as documented escape hatch.

If both A and B are unviable (Humanoids declines, fan-project takedown received), execute Track C with the documented 1-month plan.

## Why this risk exists at all

The architecture is the design statement, not the IP. The IP is the showcase for the architecture. This makes Track C *possible* — but Tracks A and B preserve the user's existing leverage, so they are preferred.
